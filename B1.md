# B1 — The Glacier cost gotcha

## 1. What happens with the original configuration?

The original lifecycle rule transitions sold listing photos to S3 Glacier Flexible Retrieval (`GLACIER`) 30 days after object creation.

S3 Glacier Flexible Retrieval has a 90-day minimum storage duration. If an object is deleted, overwritten, or transitioned to another storage class before completing those 90 days, AWS applies a prorated early-deletion charge for the remaining minimum storage period.

### Example

| Event | Day |
|---|---:|
| Photo uploaded | 0 |
| Photo transitions to Glacier | 30 |
| Seller requests deletion | 40 |
| Deletion deadline | 70 |
| Glacier minimum duration completed | 120 |

At day 40, the object has spent only 10 days in Glacier. If deleted immediately, 80 days remain in the 90-day minimum storage period.

The early-deletion charge is approximately the Glacier storage rate for the object's size multiplied by those remaining 80 days. The exact amount depends on the AWS Region, object size, and applicable pricing.

AWS also documents 40 KB of additional metadata per object archived to Glacier Flexible Retrieval: 32 KB billed at the Glacier rate and 8 KB at the S3 Standard rate. Transition requests are an additional cost.

References:
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/glacier-storage-classes.html
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/troubleshoot-lifecycle.html
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-transition-general-considerations.html

## 2. Redesigned storage strategy

Use S3 Intelligent-Tiering for sold listing photos instead of transitioning them directly to Glacier Flexible Retrieval.

Reasons:
- Intelligent-Tiering has no minimum storage duration.
- The application can permanently delete an object when a valid seller deletion request is received, without incurring the Glacier 90-day early-deletion charge.
- Its automatic Frequent, Infrequent, and Archive Instant Access tiers can reduce storage costs while retaining low-latency access.
- Do not enable the optional asynchronous Archive Access or Deep Archive Access tiers for this deletion-sensitive workload.

Intelligent-Tiering has a per-object monitoring and automation charge, and lifecycle transitions have request costs. These must be included in the storage budget.

## 3. Lifecycle scope

The Terraform lifecycle rule uses an object tag filter:

- Key: listing_status
- Value: sold

The application must apply this object tag when a listing is sold. The lifecycle transition is then scoped to matching objects rather than every object in the bucket.

The transition occurs 30 days after object creation. This is not 30 days after the tag is applied.

## 4. Seller deletion workflow

1. Receive and authenticate the seller's deletion request.
2. Record the request timestamp and calculate the deletion deadline (within 30 days).
3. Mark the listing and its associated objects as pending deletion so they are no longer exposed to users.
4. Identify all associated objects, versions, and replicas covered by the deletion policy.
5. Permanently delete the required data using the application deletion workflow.
6. Verify deletion and record the result for audit purposes.
7. Alert and escalate before the 30-day deadline if any deletion remains incomplete.

The application owns the deletion SLA. S3 lifecycle transitions must not be treated as a substitute for processing seller deletion requests.

## 5. Cost controls and operational safeguards

- Monitor object counts and bytes by storage class.
- Track Intelligent-Tiering monitoring charges and lifecycle transition request costs.
- Review object-size distribution before enabling automatic tiering for large numbers of small objects.
- Use S3 Storage Lens and AWS Cost and Usage Reports to identify storage-class cost changes.
- Create AWS Budgets alerts for storage spending.
- Test the deletion workflow, including object versions and replicas, before production rollout.

## Conclusion

The original design uses a 90-day minimum-duration archival class for data that may need to be deleted within a 30-day request SLA. This creates an avoidable early-deletion cost.

S3 Intelligent-Tiering without optional asynchronous archive tiers is a better fit for these seller-deletable photos. It preserves automatic storage optimization while avoiding the minimum-duration penalty associated with Glacier Flexible Retrieval.
